# Synopsist

Official music website and audio analysis project. Synopsist reads personal moments to generate tailored playlists with songs that have a high resonance with user's musical tastes. 

> Built in mind for artists and music producers, though anyone who enjoys music can still use Synopsist.

Live at: oslohaggadone.github.io/Synopsist/
This project lives in the `Synopsist/` folder of
[OsloHaggadone/oslohaggadone.github.io](https://github.com/OsloHaggadone/oslohaggadone.github.io)

## Setup

Runs in WSL (Ubuntu) with Python 3.14.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python scripts/build_catalog.py   # analyzes every song, builds data/synopsist.db and the website's music library
python app/server.py              # runs the website and its listening API at http://localhost:8000 (Ctrl+C stops it)
python scripts/listening_log.py   # what's been listened to: the latest events (--replays: every jump back that counts)
python scripts/pull_events.py     # downloads the live site's listening data to data/live.db (see below)
(cd worker && npm test)           # the live API's tests (Node.js; see below)
python -m pytest                  # runs the tests
```

## The website

Plain HTML, CSS, and JavaScript. Style is inspired from the UI design from Arcaea. 

Playback Features/Controls:
Song details (D-key). Displays a written summary from player/song-notes.md:

a complexity rating out of 100
tempo, key, loudness stats, and notes per second
the bass/mid/high balance
a clickable moment-by-moment timeline

Full screen (F-key). Seek bar hides during playback on desktop:

Backgrounds react to the bass, mids, and highs. Color palette is taken directly from the given album cover artwork. Popular songs get their own unique design and VFX.

Settings (saved in the browser):

Theme: one of four album palettes, plus Auto, Light, or Dark
Graphics: High, Low, or Off
Sound: EQ, live EQ display, Enhance audio (volume matching, on by default), and crossfade

Also.

Phone layout like a music app
Lock-screen and media-key controls
Keyboard shortcuts
Reduced-motion support
iPhone Home Screen install (see #app)
Fonts: Kazesawa and Exo, subsetted in player/fonts/ (SIL OFL)

Loudness. Songs are matched to -14 LUFS by adjusting each MP3 frame’s gain (like mp3gain), with no re-encoding. The originals in data/stream/ are never changed. 

## How the audio analysis works

Each song is analyzed once with [Essentia](https://essentia.upf.edu/): Discogs-EffNet embeddings
(a 1280-number description of the sound, about once per second) and what Essentia's classifiers
hear in them (instruments, moods and themes, genres, voice, danceability), beats and tempo, onsets,
key and chords, the main melody and its notes, loudness, loudness range, and dynamic complexity,
how dense the sound is, and how much bass, mids, and highs there are at each moment. The results are cached in a SQL database, then every song is cut into 4-second segments. Each segment gets its own embedding, tempo, key, onset rate, and loudness. Listening data will be
matched to these segments, and segments with similar embeddings sound alike, which is what the
recommendations build on.

Each song's chorus is found from the same analysis (`src/synopsist/structure.py`): the song is cut
into sections where its sound changes, and the chorus is the sections in its top tier of intensity
(loudness, bass, highs, and how dense the sound is), each starting at the moment it lands, on the
beat. Most of these songs are instrumental, so that means their fullest parts, usually right after
a build or a break. Where it's wrong, `player/song-effects.js` can input a song's chorus times manually.

## Running the listening API online

The live site's listening API runs on
[Cloudflare Workers](https://workers.cloudflare.com); events go into D1, Cloudflare's SQLite database.

```bash
cd ~/OsloHaggadone/Synopsist/worker
npm install                                   # wrangler, Cloudflare's tool (already done on this computer)
npx wrangler login                            # opens the browser: sign up or log in, then Allow
npx wrangler d1 create synopsist-events       # makes the database; put its database_id in wrangler.toml
npx wrangler d1 migrations apply synopsist-events --remote   # makes its events table
npx wrangler deploy                           # prints the API's address: https://synopsist-events.<you>.workers.dev
```

## Layout

```
player/          the website: index.html, style.css, site.js (your text and links), song-notes.md
                 (what each song's details say about it), song-effects.js (songs' background
                 effects), js/, fonts/, images/
player/library/  generated by build_catalog.py: catalog.json, covers, audio copies, each song's analysis
app/server.py    web server: serves the website and the listening API (POST /events)
worker/          the live site's listening API on Cloudflare Workers (src/index.js, migrations/, tests)
src/synopsist/   core library: audio analysis, publishing, events, recommendations
scripts/         command-line tools (build_catalog.py runs the whole offline pipeline)
notebooks/       exploration only
tests/
data/            not committed, except catalog.csv
models/          not committed: Essentia model files (downloaded automatically)
```
